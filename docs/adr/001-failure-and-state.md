# ADR 001: 失敗の可観測性と送信済み状態の保全

- 日付: 2026-10-02
- 状態: 提案（本PRのレビュー・CI・通常マージを経て採用）
- 対象: [Issue #3](https://github.com/Y-Kanekoo/rss-to-discord/issues/3)

## 背景

従来はDiscord送信の一部失敗でもexit 0となり、JSON破損を空状態に置き換えました。
また、プロセスを非ゼロ終了にするだけではActionsが後続の状態commitを飛ばし、
同じ実行で成功済みの投稿まで次回重複送信します。送信とGit永続化は別の成功条件です。

## 決定

1. 状態ファイル欠落だけを初回実行と扱う。不正JSON・型不正・読取失敗は送信前に停止し、元ファイルを保持する
2. 同じディレクトリの一時ファイルへ書き、flush/fsync後にreplaceする。送信前に保存可能性を確認し、各2xx成功応答後にも保存する
3. 最初の最新5件ポリシーは維持する。初回に除外した過去分とlast_checkedを先に保存し、失敗分が再度の初回制限で除外されないようにする
4. GUID重複を選択前に除く。明示的な429のみ1回再試行し、待機は有限の0〜60秒。タイムアウト・接続例外は即時再試行しない
5. stdout末尾にJSONを出す。`status`, `dry_run`, `selected`, `sent`, `failed`, `delivery_unknown`, `unpersisted_sent`, `errors`を機械判定に使う。失敗はexit 1、正常または明示的dry-runはexit 0。URL・例外本文・投稿本文はログに出さない
6. 通知stepが失敗しても状態の永続化stepを実行する。通知stepの失敗は隠さず、job全体を失敗のままにする
7. 状態永続化は最新mainの一時worktreeへGUID和集合だけを反映し、通常pushを最大3回試行する。現在のcheckoutをresetせず、他のコード変更を上書きしない。不明な追加キーの衝突や壊れたremote状態は停止する。remote状態が欠落している場合は送信元checkoutのHEADにも存在しなかった初回だけ生成を許し、並行削除を空状態として扱わない
8. 永続化失敗時は検証済みローカル状態のみを回復artifactに保管（7日）。権限は既存contents:writeを維持。Secrets、環境、ログ、リポジトリ全体はartifactに含めない。main以外の手動実行は通知jobを起動しない。送信開始時のcheckoutはtrigger SHAでなく最新mainを使い、待機したrunによる古い状態の再利用を避ける

## 代替案と不採用理由

- 破損状態を空に戻す: 大量重複送信を招く
- 1件失敗で成功分も破棄する: 次回の重複を招く
- 送信失敗をcontinue-on-errorで緑にする: 失敗が監視できない
- 強制pushや古いcheckoutのJSONによる上書き: 並行する送信履歴やコード変更を失う
- キュー・DB・別通知サービスの導入: 今回の小さい修正範囲を超える

## 保証と限界

これはexactly-once配送ではありません。Discord受付後の応答消失、2xx応答直後かつ
ローカル保存前の停止、runnerの強制終了、ディスク障害、artifactアップロード自体の失敗では
重複の可能性が残ります。`sent`は2xx応答を得た件数で、Gitへの永続化成功件数ではありません。
`unpersisted_sent`が非ゼロなら以後の送信を停止し、確認済みだが保存できなかった件数を示します。
`delivery_unknown`はタイムアウト・接続例外で結果不明の件数です。

失敗分はsent_guidsに加えません。通常の再実行で成功分をスキップし、失敗分を再試行しますが、
記事本文の永続キューは作らないため、フィードから消えた記事の自動再送は保証しません。
同じ状態を同時に操作する複数のローカルsenderは対象外です。Actionsの既存concurrencyを維持します。

## 復旧

元の壊れた状態や最新mainを空JSONへ戻さないでください。直前の正常な履歴、最新main、
検証済み回復artifactとDiscordの実投稿を照合して、確認できる送信済みGUIDの和集合を復元します。
追加メタデータに矛盾があれば手動判断します。回復artifactはrunner停止や書込不可では生成できない場合があります。
永続化失敗の未復旧中に次回の予定実行が来ると重複し得るので、運用担当者は失敗通知を確認して速やかに対応してください。

## 検証

機能別のunit、モックHTTPを使うCLI、ローカルbare Gitの競合integration、既存CIを組み合わせます。
実Discordへの投稿、手動workflow起動、Secrets値の参照は検証に使用しません。
